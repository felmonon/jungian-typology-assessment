# Known gaps

What Pagewright 0.1 does not do, does not do well, or has not proved. Each gap says what a person
would notice and, where it isn't obvious, what would close it. IDs are stable references (the
feature matrix and research notes link to them), grouped here by topic. Features that are simply not built yet are also listed in
the [roadmap](roadmap.md).

## Compatibility and fidelity

### G-01

**Pagination is not verified against Word.** Pages are laid out by the WordCraft engine's own
line-breaking and pagination. Page counts agree with LibreOffice, an independent renderer, on all
10 fixtures (48 = 48 on the long document), and page-1 renders differ by RMSE 0.004 to 0.187 (the
same line breaks with small differences in vertical spacing; see
[evidence](evidence/pdf-vs-libreoffice.json) and the [contact sheet](evidence/pdf-vs-libreoffice.png)).
Word's own algorithm is not public (finding W-14), so documents may break onto different pages
than in Word. *Closes with:* the same fixtures laid out in Word and compared page by page.

### G-02

**Missing fonts are shown with a stand-in.** Word's default font, Aptos, is not freely
redistributable and is not installed here, so documents that use it (including Pagewright's new
documents, which follow the Office default) lay out with a substitute whose widths differ. Line
breaks and page counts can differ from a computer that has Aptos. The font control says when the
font is a stand-in, and the file keeps the original font name. *Closes with:* a
metric-compatible open font, or testing on a machine with Office fonts installed.

### G-03

**Word compatibility has not been verified.** No file written by Pagewright has been opened in
Microsoft Word, because Word was not available in this environment (Linux container, no Windows
or macOS host). What has been checked instead: every saved DOCX passes Microsoft's open-source
Open XML SDK validator (Office 2019 schemas, 0 errors), and LibreOffice opens all re-saved files
with the same page counts. Neither proves Word opens them identically. *Status:* **unperformed**.
*Closes with:* opening `docs/samples/*.docx` and the round-trip outputs in Word for Windows and Mac
and recording the result.

### G-04

**The corpus is synthetic.** The 10 DOCX fixtures and 5 damaged files are generated by
`fixtures/generate.py` (python-docx plus hand-written XML). Real documents written by Word, Google
Docs and others over many years, with their quirks, have not been tested. *Closes with:* a
licensed corpus of real-world documents run through `tools/roundtrip_check.py`.

### G-15

**The fidelity guard counts; it doesn't compare values.** It compares the number of text
characters per story, watched elements, elements in other namespaces and package parts between
the original and an untouched re-save. A property whose value changes, without an element
disappearing, isn't reported (for example a colour written differently or a measurement rounded).
It found the deliberately unsupported content and gave no false alarms on the 9 clean fixtures.

## Editing features not yet built

### G-07

**Comments and tracked changes have no interface.** They come through open → save unchanged
(verified in the foundation round trip), but there is no way to see a list of them, add, reply
to, accept or reject them in Pagewright yet.

### G-08

**Password-protected documents can't be opened.** Pagewright explains this in plain language. The
engine can decrypt documents, but Pagewright has no password prompt yet.

### G-10

**Pictures and tables can't be resized by dragging.** Pictures go in at their natural size, never
wider than the text column. Picture sizes and column widths from files are kept. Cropping and
text wrapping aren't available.

### G-11

**Different first-page or odd/even headers can't be switched on.** They are shown and kept when a
file has them.

### G-13

**No spelling check in the interface.** No underlines, suggestions or language settings.

### G-14

**Styles can be applied but not created or edited.**

Also not yet: footnotes and endnotes, section breaks, columns, equations, text boxes, a table of
contents, mail merge, citations, page borders and watermarks. See the [roadmap](roadmap.md).

## Platform and accessibility

### G-05

**Not tested with screen readers.** The interface publishes names, roles and states through
AccessKit, and the tests read that tree (8 tests, `crates/pagewright-ui/tests/accessibility.rs`).
That isn't the same as using it with NVDA, JAWS, VoiceOver or Orca, which has not been done. The
page itself is drawn as an image, with the current paragraph's text and the page number exposed.
Reading by line, word or character, and announcing formatting, are not yet available.

### G-06

**Verified on Linux only.** The code uses cross-platform libraries (eframe/wgpu, arboard, rfd,
craft-print), but it has not been compiled or run on macOS or Windows. Keyboard shortcuts use ⌘ on
macOS by design, untested there. There is no installer, signing or notarisation.

### G-09

**Printing is verified on a virtual printer only.** A print job reached the CUPS-PDF printer from
the real window. Physical printers, printer-specific options (duplex, trays) and the macOS and
Windows spoolers are untested.

### G-12

**Input methods are untested.** Pre-edit text from an input method is drawn at the caret and
committed on confirm, but no real IME (Chinese, Japanese, Korean) was used to test it.

### G-16

**High-density displays are untested.** Page textures are rendered at the window's pixel density,
but every check ran at scale 1.0 in Xvfb.

### G-17

**No drag and drop.** Files and pictures can't be dropped on the window. Use Open or Insert
picture.

### G-18

**One document per window, one window.** Opening another document replaces the current one,
after asking about unsaved changes. Running a second copy of the app gives a second window.

### G-19

**Recovery copies can be up to 10 seconds behind.** A copy is written at most every 10 seconds
after a change, so a crash can lose the last few seconds of typing. Recovery can be turned off
with `PAGEWRIGHT_NO_RECOVERY=1`.

## Upstream engine and tools

### G-20

**Two of the vendored engine's own tests fail here** (1,919 pass). One shapes Myanmar text and
needs a Myanmar font this machine doesn't have. The other is an inline text box that resizes to
fit, which lays out on 3 pages instead of 2; the cause has not been determined. Neither feature is
exposed in Pagewright. Details: [evidence](evidence/foundation-tests.txt).

### G-21

**poppler prints a warning on Pagewright's PDFs:** "Suspects object is wrong type (boolean)".
The PDF writes `/MarkInfo << /Marked true /Suspects false >>`, and ISO 32000-1 (Table 321)
defines `Suspects` as a boolean, so the file follows the standard. poppler 24.02 renders and
extracts text from these files correctly despite the message. A dedicated PDF/UA or PDF/A
validator (such as veraPDF) has not been run.
